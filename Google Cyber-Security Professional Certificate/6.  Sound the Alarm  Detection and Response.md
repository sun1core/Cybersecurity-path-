
## Module - 1 Introduction to Detection & Incident Response

### The Incident Response Lifecycle
###### Incident 
- An occurrence that actually or imminently jeopardizes, without lawful authority, the confidentiality, integrity or an information system, or constitutes a violation or imminent threat of violation of law, security policies, security procedures or acceptable use policies.

###### Event
- An observable occurrence on a network, system or device. 

##### The 5W's of an Incident;
1. Who triggered the incident
2. What happened
3. When the incident took place 
4. Where the incident took place 
5. Why the incident occurred

##### Apply the NIST of vishing Scenario
1. Preparation: the planning and training process
2. Detection & analysis: the detect and access process
3. Containment, eradication & recovery: the minimize and mitigate process
4. Post-incident activity: the learning process


#### Incident Response Operations;
###### Computer Security Response Teams ( CSIRT )
- A specialized group of security that are trained in incident management and response

##### Roles in CSIRT 
1. Security Analyst
    - Analyzing and triggering alerts 
    - Performing root-cause investigations
    - Escalating or resolving alerts

2. Technical Lead
    - to manage all aspects of the incident response such as applying software patches or updates 

3. Incident Coordinator 
     - an incident also requires cross-collaboration with non-security professionals.

### Security Operations Center ( SOC )
- an organizational unit dedicated to monitoring networks, systems, and devices for security threats or attacks.

##### SOC Roles;
1. Tier 1 SOC Analyst
    - monitoring, reviewing and prioritizing alerts based on critically or severity 
    - creating and closing alerts using ticketing systems

2. Tier 2 SOC Analyst 
    - receiving escalated tickets from L1 and conducting deeper investigations.
    - configuring and refining security tools
    - reporting to the SOC lead

3. Tier 3 SOC Analyst 
    - managing the operations of their team.
    - exploring the methods of detection by performing advanced techniques such as malware & forensics analysis 
    - Reporting to the SOC manager

4. SOC Manager
    - Hiring, training and evaluating the SOC team members
    - creating performance metrics and managing the performance of the SOC team
    - Developing reports related to incidents, compliance and auditing
    - Communicating finding to stakeholders such as executive management

#### Investigate Packet Details;
1. IP ( Internet Protocol )
- Ip ensures that packet reach destination with two versions ipv4 & ipv6. Both version use different headers to structure packet information 

     ##### IPV4;
     - version
     - internet header length ( IHL )
     - Type of Service ( ToS )
     - Identification 
     - flags
     - fragment offset
     - Time To Live ( TTL )
     - Protocol 
     - Header checksum
     - Source address

     ##### IPV6;
     - version
     - traffic class
     - payload length
     - next header 
     - hop limit
     - source address 
     - destination address


2. Wireshark 
- open-source network protocol analyzer
     ##### List of some protocols filter for;
     - dns
     - http
     - ftp
     - ssh
     - arp telnet
     - icmp


     Example; 
     1. Filter for a Ip address;
     ---> ip address == 172.21.224.2

     ---> IP.src == 10.10.10.10

#### Packet Inspection
**Command** => sudo tcpdump -i any -v -c1
### command => sudo tcpdump (-i interface) (options) (expressions)
     Example;
     1. sudo tcpdump -i any -c3 
         -w ---> write or save the sniffed network packets
         -r ---> read 
         like ---> sudo tcpdump - i any -w packet capture.pcap 
         sudo tcpdump -r packetcapture.pcap
     -v, -vv, -vvv ---> Verbosity
        sudo tcpdump -r packetcapture.pcap -v
     -c stabds for count
        sudo tcpdump -i any -c3

        sudo tcpdump -r packetcapture.pcap -v -n

# LABS


1. Identify Network Interface 
---> `sudo ifconfig
- Identify the interfaces option available for packet capture 
---> `sudo tcpdump -D

2. Inspect the network traffic of a network interface with tcpdump 
---> `sudo tcpdump -i eth0 -v -c5
-i eth0: capture data specifically from the eth0 interface
-v: display detailed packet data
-c5: capture 5 packets of data

3. Capture network traffic with tcpdump
---> `sudo tcpdump -i eth0 -nn -c9 port80 -w capture.pcap &`
-i eth0 ---> capture data from from the eth0 interface
-nn ---> not attempt to resolve IP address or ports to names.
-c9 ---> capture 9 packets of data and then exit
port 80 ---> filter port 80
-w capture.pcap ---> saved the captured data to the named file 
& ---> instruction to the bash shell to run the command in background

- use curl to generate some HTTP ( port 80 ) traffic
---> curl opensource.google.com
- verify that packet has been captured 
---> ls -l capture.pcap


4. filter the capture packet data 
--->  `sudo tcpdump -nn -r capture.pcap -v`
-nn ---> disable port and protocol name lookup
-r ---> read capture data from the named file
-v ---> display detailed packet data 

`sudo tcpdump -nn -r capture.pcap -X `
-X ---> display the hexadecimal and ASCII output format packet data
